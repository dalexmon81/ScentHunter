# ScentHunter 2.0 — Offer-First repository audit

Snapshot: 2026-11-21
Repository: dalexmon81/ScentHunter
Production/default branch: main
Working branch: architecture/offer-first-v2
Scope: read-only Git tree and source inspection through GitHub. No production runtime, secrets, mounted volumes, or local working-tree state were accessed.

## Executive result

The repository already contains reusable canonical-catalog infrastructure, SQLAlchemy models, Alembic migrations, PostgreSQL driver support, a provider-neutral StoreConnector contract, a Notino feed adapter, and a read-only catalog search API. However, the documented active pilot still defaults to a persistent SQLite catalog and the primary public path remains legacy. This is not a clean Offer-First implementation yet.

Do not rebuild the frontend, retailer parsers, product identity, schema, or connector contracts before checking/reusing these existing components. Do not delete data or legacy runtime in this audit.

## Existing reusable Offer-First foundations

- backend/app/db.py supports both SQLite and PostgreSQL, forces psycopg 3 for PostgreSQL, bounds pool connections, and configures SQLite WAL.
- backend/alembic/ contains migrations 0001 through 0005.
- backend/app/models/catalog.py contains canonical catalog SQLAlchemy models.
- backend/app/connectors/base.py defines a provider-neutral StoreConnector with discovery, product fetch, offer fetch, price/stock refresh, normalization, and common validation.
- backend/app/connectors/notino_feed.py implements Notino's authorized CJ/VIV feed as one source. Feed is a full snapshot cached per connector instance; this is a source capability, not a product-targeted public search endpoint.
- backend/app/workers/notino_runtime.py implements asynchronous ingestion orchestration and persistence for Notino.
- backend/app/search/catalog.py and backend/app/api/catalog_search.py provide catalog-backed search/status API and browser demo.
- backend/scenthunter_next_engine/ contains canonical matching, normalization, offer aggregation, URL hygiene, migration audits, baseline jobs/reports and identity references.
- backend/scrapers/ contains existing retailer-specific code, including Notino, Easycosmetic, Parfumzentrum, Sabina and Deloox. Presence of a scraper does not prove runtime health or actual verified offer coverage.
- Tests exist for catalog search, identity, Notino discovery/feed/runtime, SQLite contention, migrations and end-to-end catalog behavior.

## Critical architecture mismatch against the new plan

1. backend/README_POSTGRESQL.md explicitly describes the current canonical pilot as SQLite and says PostgreSQL is a later separately reviewed migration.
2. backend/app/db.py defaults to sqlite:////data/catalog/catalog.sqlite3 unless an environment variable changes the URL.
3. docs/architecture/catalog-first-status-2026-11-20.md says the production database migration and verified restore are not evidenced.
4. The new project objective is live query-driven, offer-first acquisition. Existing Notino adapter is catalog/feed ingestion, not yet a unified request-scoped targeted search capability. The new acquisition contract needs a separate bounded search_products() operation that can use authorized feed indexes or retailer search endpoints without turning user requests into broad crawls.
5. Existing catalog search reads internal indexed data. The Offer-First search path must be designed as a resilient fan-out over fresh stored offers plus bounded targeted acquisition when coverage is missing.
6. PostgreSQL driver and migrations existing in the repo must not be interpreted as proof that production runs PostgreSQL.
7. The matching directory currently has only a README at the inspected path; canonical matching logic is located in scenthunter_next_engine and legacy product_matcher. Reuse/relocate only after imports and test coverage are audited.
8. User-defined plan says use PostgreSQL. Resolve earlier architecture docs and deploy environment before activating PostgreSQL; do not silently continue SQLite under a PostgreSQL label.

- backend/__pycache__/*.pyc: generated Python bytecode; do not check into source control.
- Add/verify .gitignore rules for __pycache__/, *.py[cod], .pytest_cache/, .venv/, local database files, and secrets. No .gitignore was found at repository root in the inspected listing.
- Temporary diagnostics may be archived later, but not deleted in this first pass.

### Do not delete yet
- tools/diagnostics/ and tools/debug/: audit notes say manual ops, legacy routes, and tests may depend on them.
- .github/workflows/: many workflows reference current deployment, ingestion, production diagnostics and recovery. Deleting by filename alone is unsafe.
- frontend/index.html: large monolithic file but it is the public interface.
- backend/product_catalog.json and family_registry.json: migration/rollback inputs.
- SQLite queue/catalog logic: production dependency has not been runtime-inspected; retire only after PostgreSQL parity and backup/restore evidence.
