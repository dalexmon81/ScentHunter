# Country-aware shipping costs\n\n## Goal\nShow the delivered cost for a buyer's destination, not just the perfume's shelf price. Product offers and retailer shipping policies are separate facts: one offer may be valid in several countries with different fees, free-shipping thresholds, delivery windows, postal restrictions and weight bands.\n\n## Data model\nstore_shipping_rates stores one retailer rule for a destination country and optional postal-code prefix, currency, base fee, free-shipping threshold, order-value bounds, weight bounds, delivery-day range, source/evidence, capture time and explicit expiry. It is separate from offers.shipping_cost, which remains a legacy per-offer field and must not be treated as a universal country tariff.\n\nStates:\n- verified: exact fee/threshold rule has a source and an unexpired valid_until; can produce a definitive delivered total.\n- estimated: indicative figure only; returns total_cost_estimate, never total_cost.\n- unavailable: retailer explicitly does not ship to that destination.\n- no matching rule, currency mismatch or expired verified rule: unknown/stale; never silently treated as free shipping.\n\n## Quote API\nGET /shipping/quote?store_slug=...&country_code=LU&order_subtotal=79.00&currency=EUR&postal_code=...&weight_kg=...\n\nThe quote engine validates ISO country/currency, chooses the most specific postal-prefix rule, applies order-value and weight conditions, applies free-shipping threshold, and returns a definitive total only for a fresh verified rule.\n\nThe current endpoint quotes one retailer/order. For product comparison, the frontend will request the quote for each offer using the product price as the one-item subtotal, then sort by delivered total only when verified. Unknown/estimated offers remain clearly labelled and cannot be ranked as confirmed landed cost.\n\n## Collection and safety\nNo retailer is activated by adding a shipping rule. Shipping data can be entered from official shipping pages, approved API/feed fields or a documented manual confirmation. Automated collection must respect each retailer's access terms and existing store-authorization gates. Do not seed fake rates into staging. Every verified rule needs evidence and expiry; expired rates stop producing totals until refreshed.\n\n## Rollout\n1. Schema, migration and deterministic quote engine (this change).\n2. Admin workflow for evidence-backed rule entry and expiry/refresh.\n3. Search response and frontend country selector integration.\n4. Add destinations incrementally: LU first, then BE/FR/DE/IT/NL.\n5. Populate only from verified retailer data and test delivered-total ordering with real authorized offers.
